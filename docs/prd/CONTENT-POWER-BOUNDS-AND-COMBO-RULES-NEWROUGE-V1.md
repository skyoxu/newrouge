# NewRouge 内容强度边界与组合禁区（v1）

用途：为“新增卡牌/遗物/事件/天赋/敌人”提供一套可执行的强度边界与组合禁区，保证内容扩展不会悄悄破坏：

- 60 分钟单局节奏（雪球过快或过慢）
- 可解释性与可读性（玩家能理解为什么强/为什么输）
- 确定性与可复现（退出重进不刷结果、QA 可复盘）

约束声明：
- 本文档只做文档规格，不做任何代码实现/dev 操作。
- 数值阈值若属于 Base/ADR/门禁脚本口径，不在此复制，只引用其来源。

## 0) 核心原则（先止损，再扩展）

1) 强度来自“组合与顺序”，不是黑箱与随机。  
2) 任何一次失败必须存在至少一条可执行改法（换牌路、换流派、修剪卡组、调整遗物/天赋取向）。  
3) 内容设计必须优先保证“可解释”：玩家能指认压力来源与对策。  
4) UI 行为不得推进 RNG；可见文本不得硬编码（见 `docs/prd/SSOT-LOCKS-NEWROUGE-V1.md`）。  

---

## 1) 压力向量定义（统一词汇，避免争论跑偏）

> 目的：把“这个东西强/难”的原因归因到可讨论的向量上。

- P1：资源压力（行动点/能量/手牌/抽牌）
  - 风险：无限资源或“资源越打越多”的失控雪球

- P2：伤害压力（爆发/持续/穿透/多段）
  - 风险：过早的一回合击杀（OTK）成为常态，压缩构筑空间

- P3：防御压力（格挡/护甲/减伤/免疫）
  - 风险：无限防御或“免疫常驻”让战斗失去决策

- P4：debuff 压力（易伤/虚弱/中毒/流血/腐化等）
  - 风险：debuff 叠加到“无对策就必死”，或与资源压制形成锁死

- P5：控制压力（跳过回合/沉默/缴械/锁牌）
  - 风险：控制链导致玩家连续失去行动权

- P6：规则改写压力（改变抽牌、出牌上限、卡牌费用规则等）
  - 风险：规则改写与遗物/天赋叠加成系统级破坏

---

## 2) 组合禁区（硬禁止，出现即视为缺陷）

### 2.1 无限循环/无上限递归

禁止出现以下任一结果（无论通过卡牌、遗物、天赋、事件组合达成）：
- 无限行动点/能量
- 无限抽牌/无限生成牌（无上限且不触发失败条件）
- “一张牌”可在同一回合被无限次重复打出（无硬上限与无代价）
- 触发器递归：`on_play` / `on_draw` / `on_damage` 等事件链可形成无终止递归

硬口径建议（用于内容审查与实现对齐）：
- 一切“触发器型收益”必须有显式硬上限或明确的资源消耗路径，且该上限必须在 UI 可解释（文本走 Translations）。

### 2.2 控制链（玩家失去行动权）

禁止任何机制形成以下体验：
- 玩家连续多个回合无法执行有效行动（被动挨打）
- 控制与资源压制叠加导致“即使不死也无法翻盘”

### 2.3 常驻免疫/常驻无敌

禁止任何组合达成：
- 常驻免疫所有伤害/所有 debuff
- 常驻无法被针对的“不可交互状态”

### 2.4 事件强度跨越（事件直接替代构筑）

禁止事件奖励直接造成：
- “不需要构筑也能通关”的系统级跳跃（例如一次事件直接给出完整终盘强度）
- 事件负面与战斗主压力同向叠加形成“必败开局”（尤其在 Act1）

## 3) 软边界（允许存在，但必须稀有且可解释）

这些现象允许在“稀有机会/史诗事件/Act3/Boss 后置”出现，但必须满足：来源可感知、代价可理解、对策可执行、能被存档与确定性复现。

- 高爆发（接近 OTK）的 build：必须有明确前置条件（如堆叠、准备回合、资源消耗），并且不是通用解
- 规则改写（P6）：必须在事件/遗物/天赋说明里清晰表达，并且不能与其他规则改写叠加成禁区
- Ultimate 机会：仅来自稀有入口（见 SSoT）；不允许常态化投放

---

## 4) 角色差异的内容审查要点（避免“换皮卡池”）

### 4.1 战士（怒气为状态 buff，不是第二属性条）

审查要点：
- 怒气相关牌的强度主要来自“节奏与代价”，而不是无脑堆叠数值
- 禁止把怒气设计成“第二资源条”并让 UI/系统围绕其独立运转（口径破坏）

### 4.2 刺客（擅长给敌人叠 debuff）

审查要点：
- debuff 叠加必须有对策窗口（敌方可清/玩家需续/有代价）
- 禁止 debuff 与资源压制/控制形成锁死组合

### 4.3 德鲁伊（状态持久 buff + 切换状态定点爆发）

审查要点：
- 状态切换必须有明确的机会成本（行动点、回合、或风险暴露）
- 禁止“无成本切换 + 爆发”导致稳定 OTK

## 5) 内容作者自检清单（增量提交前 5 分钟）

1) 这条内容主要落在哪些压力向量（P1–P6）？是否与现有内容叠加触达禁区？  
2) 是否引入任何新的“触发器链”？是否存在无上限递归风险？  
3) 是否影响确定性（例如 UI 行为推进 RNG、候选集不锁定、退出重进可刷）？  
4) 是否违反“商店不升级”“升级路线不可逆”“Ultimate 稀有不可逆”等锁定项？  
5) 可见文本是否已规划为 Translations key（派生自稳定 ID）？
