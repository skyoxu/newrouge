# NewRouge v1 玩家可解释反馈输出规格（事件/奖励/升级/存档）

用途：把“允许随机，但必须可解释且可复现”的反馈输出做成策划/QA/研发可直接执行的规格，覆盖：
- 事件（含代价与收益）
- 三选一/多选一奖励（含候选集锁定）
- 卡牌升级（休整升级 / 事件路线重选 / Ultimate 机会）
- Continue/存档边界（退出重进不刷结果）

约束声明：
- 本文档只做文档规格，不做任何代码实现/dev 操作。
- 本文档不创建任何 `docs/contracts/**` 类型的契约文件。

权威引用：
- v1 锁定表（SSoT）：`docs/prd/SSOT-LOCKS-NEWROUGE-V1.md`
- 存档/确定性（Offer locking、UI 不推进 RNG）：`docs/adr/ADR-0032-save-resume-determinism.md`
- 内容稳定 ID 与翻译 key：`_bmad-output/content-id-standard.md`
- 文案/本地化硬口径：`project-context.md`

## 0) 总原则（v1）

1) 随机必须“可解释且可复现”
- 玩家必须能理解“这次出现了什么/我选了什么/发生了什么代价与收益”。
- QA 必须能通过 seed + 输入序列复盘同一结果（退出重进不刷结果）。

2) 可见文本不硬编码
- 所有可见文本走 `Game.Godot/Translations`；key 由稳定 ID 派生。

3) 关键信息默认展示，细节可折叠
- 默认展示：结果摘要 + 关键数字/关键对象（卡牌/遗物/事件 ID 关联的显示名）
- 细节（可选展开）：provenance、候选集 id 列表、日志条目 id

---

## 1) 事件（Event）结果面板：最低显示字段

事件面板（进入事件时）必须显示：
- 标题与描述（Translations）
- 每个选项的：标签（label）+ 风险/代价提示（短句）

事件结果面板必须显示（最低要求）：
- 你选了哪个选项（A/B 或选项名）
- 发生了什么（effects summary）
- 关键数字（金币、HP、状态回合数、获得/失去的卡牌或遗物数量）

建议格式（短句）：
- `代价：金币 -10，生命 -5`
- `收益：获得 1 张卡牌（稀有）`
- `状态：中毒 2T`

---

## 2) 三选一/多选一奖励：必须解释“可复现”

奖励面板必须显示：
- 候选项（3 个或 N 个）
- 每个候选项的显示名与一行摘要（Translations）

奖励面板（可折叠/可选显示）应当展示：
- `候选集已锁定`（明确告知退出重进不会刷新）
- provenance 摘要（例如：来自哪个节点/哪个事件/哪个战斗结算）

禁止语境：
- 任何暗示“退出重进可以换候选/换结果”的文案。

---

## 3) 升级系统：必须解释“你在做不可逆选择”

### 3.1 休整节点免费升级

休整节点的升级选项必须明确：
- `免费升级 1 张卡牌`
- `升级为二选一（不可逆）`

### 3.2 U1 路线选择（Route A/B）

升级界面必须显示（最低要求）：
- 当前卡牌 base 的名称/描述
- Route A 的名称/描述（Translations key：`.u1a.*`）
- Route B 的名称/描述（Translations key：`.u1b.*`）
- 明确警告：`选择后不可逆`

### 3.3 特殊事件：U1 路线重选

必须明确：
- 你可以在事件内来回切换（不限制次数）
- 离开事件时以“最终选择”为准
- 该过程不会改变其他随机结果（UI 不推进 RNG）

### 3.4 Ultimate（终极形态）

必须明确：
- 稀有机会（来源要能被玩家识别：事件/ Boss 等）
- `不可逆`、`不可再升级`、`不可换路线`

---

## 4) Continue/存档边界：必须解释“为什么回到战斗初始”

当玩家在战斗中退出/崩溃/断电后继续游戏：
- 必须明确告知：恢复到“战斗初始状态”
- 不得出现“回到战斗中间”的暗示

当存档损坏/迁移失败时：
- 必须阻断 Continue 并提示（可恢复/可联系客服/可提交日志）

---

## 5) 最小禁用词清单（内容与 UI 一律避开）

禁止出现以下语境（会引导玩家刷结果或误解系统）：
- “退出重进可以换结果”
- “战斗中断点续打”
- “商店升级”
