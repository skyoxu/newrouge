# NewRouge v1 逐屏玩家体验规格（闭环可执行版）

用途：把 v1 的“闭环体验结构”落成逐屏可执行规格，方便策划/QA/研发在不读完全部文档的情况下：
- 逐屏对齐：关键展示字段、默认主动作、确认/回退边界
- 快速发现：UI 文案误导（尤其是存档/确定性/升级不可逆）
- 为回归基线与证据归档提供固定检查点

约束声明：
- 本文档只做文档规格，不做任何代码实现/dev 操作。
- 本文档不创建任何 `docs/contracts/**` 类型的契约文件。

权威引用（本文件只做整合，不重复发明规则）：

## 0) 全局体验硬约束（v1）

1) 单槽 autosave + Continue 入口  
- 主菜单只有一个 Continue（读取单槽 autosave）。  
- 新开一局允许覆盖旧 autosave，但必须二次确认，且覆盖不可撤销。

2) 退出重进允许，但不刷结果  
- 退出重进不改变事件/奖励候选集与结果空间（同一输入序列保持确定性）。  
- 三选一候选集必须锁定（stable ids + 顺序 + provenance），UI 行为不得推进 RNG。

3) 存档粒度固定  
- 节点前存档；进入战斗只存“战斗初始状态”；战斗中绝不保存中间态；战斗中退出重进回到战斗初始状态。

4) 升级系统口径固定  
- 商店任何时候都不能升级。  
- 休整节点升级：多选一选项之一；若选择升级则免费升级 1 张。  
- U1：Route A/B 二选一不可逆；特殊事件内可无限次切换路线，离开事件以最终选择为准；Ultimate 稀有不可逆且不可换路线。

5) 文案与可见文本  
- 所有可见文本必须走 `Game.Godot/Translations`；脚本里禁止硬编码可见文本。

## 1) MainMenu（主菜单）

目的：让玩家 1 次操作即可开始闭环（继续/新局），并且不会误解存档规则。

必须展示：
- 版本号（用于回归定位）
- `新游戏` / `继续游戏` / `设置`（可选）/ `退出`
- 若存在 Continue：显示“上次运行摘要”（可选但推荐），至少包含：难度档位、进度位置（Act/节点类型）

边界与错误：
- Continue 若被阻断（坏档/迁移失败/校验失败）：必须提示原因，并提供“查看日志/返回主菜单”的可恢复路径（不得崩溃）。

验收点（最小）：
- 冷启动点击 `新游戏` 能进入新局流程；热启动点击 `继续游戏` 能进入 Continue 流程；Continue 被阻断时不会进入游戏内。

---

## 2) NewGame Overwrite Confirm（覆盖确认）

目的：避免玩家误操作覆盖唯一 autosave。

触发：
- 玩家在已有 autosave 的情况下选择 `新游戏`。

必须展示：
- 明确文案：将覆盖当前进度，且不可撤销（避免误解为“另开存档槽”）。
- 二次确认：`取消` / `确认覆盖`（默认焦点必须是 `取消`，降低误操作）。

验收点（最小）：
- 默认焦点=取消；取消不会改变现有 autosave；确认覆盖后旧进度不可再通过 Continue 访问。

---

## 3) Difficulty Select（难度选择，10 档）

目的：让玩家明确这是“数值挑战曲线”，不误以为与天赋树强绑定。

必须展示：
- 难度档位 1..10（显示当前选中档位）
- 一句解释：难度影响敌人与奖励曲线（不引入复杂规则变体语境）
- 明确说明：难度与天赋树不强绑定（避免玩家误解为“必须刷天赋才能打高难”）

验收点（最小）：
- 选择难度后进入角色选择/开局流程；返回不会覆盖 autosave。

---

## 4) Hero Select（角色选择）

目的：让玩家理解三角色的机制差异，而不是“换皮卡池”。

必须展示：
- 三角色：战士/刺客/德鲁伊
- 每个角色 2–3 行短机制说明（不写长段落）
- 角色机制口径必须符合 GDD/SSoT（怒气为状态 buff；刺客偏 debuff；德鲁伊姿态切换）

验收点（最小）：
- 角色机制描述不引入不存在的第二属性条或误导性描述。

---

## 5) Meta Progression（天赋树 / 元系统）

目的：让玩家理解“共享天赋树可无条件重置”，并明确重置后不会改变已发生的 run 结果。

必须展示：
- 天赋树（共享）
- `重置天赋` 入口（无条件）
- 清晰提示：重置影响未来 run 的规则/权重，不回溯改变已完成的 run

验收点（最小）：
- 重置入口存在且不隐藏；提示语不把它描述为“不可逆”或“消耗稀缺道具”（与口径冲突）。

---

## 6) Act Map（分叉路线图 / 节点选择）

目的：让玩家在“进入节点前”做决策，符合节点前存档边界。

必须展示：
- 当前 Act 与节点路线分叉（可见的路径选择）
- 节点类型（至少：战斗/事件/商店/休整/精英/首领）
- 当前资源概览（HP、金币、关键状态摘要）

边界：
- 进入节点前就是存档边界：进入节点后退出重进不得回滚到进入前改路（除非明确在“节点前”退出）。

验收点（最小）：
- 节点选择有确认动作；确认后进入节点；退出重进遵循存档边界。

---

## 7) Event Node（事件节点）

目的：提供“代价与抉择”，并且结果可解释且不被退出重进刷掉。

必须展示：
- 标题/描述/选项（Translations）
- 选项的代价与收益提示（短句）

若事件包含奖励三选一：
- 必须显示“候选集已锁定”语义提示（避免玩家尝试退出重进刷结果）

验收点（最小）：
- 同一 run 内事件不重复（按 event_id）；三选一候选集锁定提示存在且不误导。

---

## 8) Shop Node（商店节点）

目的：提供卡组与资源的“可控改进”，但绝不提供升级。

必须展示：
- 可购买内容（卡/遗物/服务等）
- 明确禁止语境：不得出现任何“升级”入口、按钮或暗示（包括“强化/升星”同义词）

验收点（最小）：
- 商店内找不到升级服务；文案不暗示“回头来这里升级”。

---

## 9) Rest Node（休整节点）

目的：提供关键的“恢复 vs 升级”分岔选择。

必须展示：
- 多选一选项（至少包含：恢复 / 升级）
- 若选择升级：明确“免费升级 1 张卡牌”
- 升级选择界面必须明确：U1 Route A/B 二选一、不可逆

验收点（最小）：
- 升级是免费且只升级 1 张；确认升级后不可逆；不引入额外随机推进。

---

## 10) Combat（战斗）

目的：战斗内决策推进 run；退出重进回到战斗初始状态（不存中间态）。

必须展示：
- 当前回合与可见状态（debuff/buff、剩余回合数/层数）
- 关键结算反馈（伤害/治疗/状态变化，数字可读）

边界：
- 进入战斗时保存战斗初始状态；战斗中退出重进只能回到初始状态。

验收点（最小）：
- 战斗中退出重进后回到战斗初始状态；不出现中间态恢复。

---

## 11) Rewards（战斗/节点奖励）

目的：给出可解释、可复现的奖励选择，并防止刷结果。

必须展示：
- 奖励来源（来自哪个节点/战斗/事件）
- 候选项（卡牌/遗物等）
- 若为三选一：显示“候选集已锁定”语义提示

验收点（最小）：
- 退出重进后候选集与顺序一致；提示语不暗示可刷新。

---

## 12) Upgrade UI（升级选择：U1 / 路线重选 / Ultimate）

目的：让玩家明确“这是不可逆选择”或“这是事件内可反复切换但离开后定稿”，并保证确定性。

必须展示：
- U1：Route A/B 的明确差异（名称/描述），并有“选择后不可逆”的明确提示
- 路线重选事件：明确“事件内可无限次切换，离开事件时以最终选择为准”
- Ultimate：明确“不可逆、不可再升级、不可换路线”

验收点（最小）：
- 文案不模糊；不会把路线重选误导成“随时可改”；不会把 Ultimate 描述成“还能继续升级”。
