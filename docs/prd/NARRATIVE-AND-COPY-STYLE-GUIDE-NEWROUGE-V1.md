# NewRouge v1 叙事与文案风格指南（黑暗主题，确定性止损）

用途：把 NewRouge v1 的叙事口吻、UI 文案结构与“禁用语境”写成可执行指南，服务内容作者与 UI 文案，确保：
- 文案不误导系统（尤其：存档边界、退出重进不刷结果、升级不可逆、商店不升级）
- 文案短、可读、可解释（60 分钟单局；大量事件与卡牌）
- 所有可见文本可本地化（Translations，不硬编码）

约束声明：
- 本文档只做文档规格与写作规范，不做任何代码实现/dev 操作。
- 本文档不创建任何 `docs/contracts/**` 类型的契约文件。

权威引用：
- v1 锁定项（SSoT）：`docs/prd/SSOT-LOCKS-NEWROUGE-V1.md`
- 可解释反馈输出规格：`docs/prd/PLAYER-FEEDBACK-EXPLAINABILITY-NEWROUGE-V1.md`
- 逐屏体验规格：`docs/prd/SCREEN-BY-SCREEN-PLAYER-SPECS-NEWROUGE-V1.md`
- 文案与本地化硬口径（Translations 禁硬编码）：`project-context.md`
- 存档/确定性（Offer locking、UI 不推进 RNG）：`docs/adr/ADR-0032-save-resume-determinism.md`
- 内容稳定 ID 与翻译 key 派生：`_bmad-output/content-id-standard.md`

## 0) 风格定位（1 分钟对齐）

核心口吻：
- 黑暗主题：克制、冷峻、有代价感，但不故作玄虚。
- 信息优先：先让玩家知道“发生了什么、代价是什么、我能怎么做”。
- 不羞辱玩家：不嘲讽失败、不说教、不把系统规则藏起来当“惊喜”。

核心禁区（与玩法硬口径强绑定）：
- 不引入“退出重进可刷结果”的语境。
- 不引入“战斗中断点续打/继续到中间”的语境。
- 不引入“商店升级”的语境。

---

## 1) 文案必须可本地化（硬规则）

1) 所有可见文本必须走 `Game.Godot/Translations`  
- 脚本里禁止硬编码可见文本（见 `project-context.md`）。

2) 内容文本 key 必须由稳定 ID 派生  
- 卡牌/遗物/事件/天赋文本 key 由 `content_id` 派生（见 `_bmad-output/content-id-standard.md`）。

---

## 2) 文案长度与结构（硬规则）

1) 单行上限（建议）
- 关键按钮/提示：尽量 <= 18 个汉字
- 事件描述：1–2 句为主，避免长段落
- 结果摘要：必须包含 1 行“代价/收益”数字摘要

2) 结果面板的最低信息架构（固定顺序）
1) 结果（成功/失败/获得/失去）  
2) 代价与收益（数字与对象）  
3) 下一步入口（继续/返回）  

---

## 3) 必须一致的关键术语（不要自创同义词）

为了降低误解成本，同一概念必须使用同一词组（Translations 里统一）：
- `继续游戏`（Continue，读取单槽 autosave）
- `新游戏`
- `确认覆盖` / `取消`（覆盖确认对话框）
- `休整`
- `商店`
- `事件`
- `升级`（仅休整/特定事件可升级；商店禁止出现“升级”）
- `终极形态`（Ultimate）
- `路线 A` / `路线 B`（U1 升级二选一）

---

## 4) 确定性与存档边界的表达规范（高风险，必须写清）

### 4.1 Continue（继续游戏）

允许说法（示例）：
- `继续游戏会读取上次自动保存的进度。`

必须说明（当玩家可能误解时）：
- `退出后继续不会刷新事件或奖励候选。`

禁止说法（示例）：
- `退出再进可能出现不同结果`
- `刷新奖励/刷新事件`

### 4.2 战斗中退出重进

必须说明（事实，不要模糊）：
- `战斗中退出后继续，将回到该场战斗的初始状态。`

禁止说法：
- `从中途继续`
- `从上一回合继续`

### 4.3 三选一奖励（Offer locking）

必须避免的误导：
- 任何暗示“可以通过退出重进换候选”的文案。

推荐提示短句（示例，二选一）：
- `候选已锁定（退出不会刷新）。`
- `候选固定（退出不会改变）。`

---

## 5) 升级系统文案规范（不可逆/可切换/Ultimate 的差异必须明确）

### 5.1 休整升级（免费升级 1 张）

必须说明：
- `免费升级 1 张卡牌。`
- `升级为二选一（不可逆）。`

### 5.2 U1 路线选择（Route A/B）

必须包含的警告短句（建议固定为同一句，避免漂移）：
- `选择后不可逆。`

禁止模糊表达：
- `之后还能改`
- `随时可重置（指卡牌升级）`

### 5.3 路线重选事件（事件内无限切换，但离开后定稿）

必须说明（事实）：
- `事件内可随意切换路线，离开事件时以最终选择为准。`

### 5.4 Ultimate（终极形态）

必须说明（事实）：
- `不可逆。`
- `不可再升级。`
- `不可换路线。`

---

## 6) 商店文案禁用语境（硬规则）

商店内禁止出现任何“升级”语境（包括同义词误导）：
- 禁止：`升级/强化/升星/进阶/改造（若玩家会理解为升级）`

允许的服务语境（示例，不绑定实现）：
- `购买`
- `移除`
- `转换`
- `重铸`

---

## 7) 事件写作规范（黑暗代价，但可解释）

1) A/B 选项必须有“可读差异”
- 至少在两项上不同：代价/收益/风险来源/对未来 build 倾向

2) 代价必须能被玩家理解为“代价”
- 不写成黑箱；必须能在结果摘要里落成数字或明确对象变化

3) 同局不重复的心理预期
- 不要暗示“你下次可能又遇到同一个事件”（同局不重复）
- 允许暗示“跨局会再遇到”（跨局可重复），但避免承诺概率
