# ADR-0053: Historical proof-v3 original-owner authentication and public history

- Status: Proposed
- Date: 2026-11-10
- Scope: Story 2.8 historical consumption of explicit adoption review v3, and versioned qualified compensation disclosure
- Related: ADR-0040, ADR-0049, ADR-0050; the distinct reader-lifetime and initial-legacy decisions retain ADR-0051 and ADR-0052 in their owning branches.
- Implementation state: R57 source integration on the recorded 907bd4 baseline; no genuine proof-v3/public-history/compensation positive execution or formal acceptance is claimed here.

## Context

ADR-0050 keeps semantic history distinct from host-only proof bytes, requires same-policy exact replay, and rejects cross-policy re-signing. Its delivery.v3/transport.v1 is a compensation material representation, not the adoption `expanded-semantics.v3` review profile. The two version families must not be conflated.

The installed successor adds an explicit historical route for `newrouge.b-route-adoption-review-proof.v3`. The old operation's immutable request, private subject, runtime, capsule, original source/policy and raw support remain authoritative history. Requiring that old recorded absences or empty Task/protection state still hold against today's target would incorrectly turn historical verification into fresh admission. Conversely, skipping the original checks or accepting a caller-approved dictionary would not authenticate that history.

## Decision

1. Select the known family from the actual journal operation. A profile-less proof.v2 keeps its original owner route. A proof.v3 requires the explicit request `review_profile: expanded-semantics.v3` and matching private/public subject versions. Unknown or mixed profile/proof/subject versions fail without fallback. Existing legacy review/decoder paths and the original thirteen-method regression scope remain; this decision does not certify their execution at the new epoch.

2. The current consumer uses a real owned read-only worker for the fixed original R56 owner. The installed adjacent `qualified-historical-owner-authority.v2.json` must bind the complete original policy source/schema set, interpreter and distinct original R52 producer-reader path/raw identity. Actual R56 modules retain their real filenames and loader/source identities. Original R52 reader `3c2b2c614082c3dcd04f5ac4866e0152fa93e4dc19ac5487853cef6731f41548` remains the producer; it is not relabelled as an R56 execution. No alias, rewritten `__file__`, arbitrary import root or caller-supplied producer verdict is permitted.

3. The real original owner validates the actual journal row; complete original request/frozen effects; original proof and ordered raw support; original public prompt/schema/serialized request; real execution/protocol/output/runtime and mandatory semantic verdict; original capsule/native provenance and retained execution; and the raw-derived historical protection archive. The entire operation-owned retained binding.v2 and its original request/material/target-authority/consumer-rule/policy/execution relations remain checked. Historical re-verification does not call fresh `_binding_value03` or `_target_facts` against today's target and does not generate another native run or model review.

4. Historical target dependencies are recovered from authenticated original archive bytes, exact retained original support, or original runtime-bound recorded absence. Absence is labelled historical, never asserted current. Any required original byte missing, wrong raw/canonical binding, unsupported family, mixed owner/policy, partial/unknown execution or contradictory evidence fails closed. The current compensation/publication owner separately rechecks actual current-before data, scopes, effects, authority and pending/journal state under its original locks. Historical authenticity alone cannot authorize a new write.

5. Only a genuine original-reader return after owned Job/process completion can mint the private current-consumer history token. A saved result dictionary, caller boolean, fabricated CompletedProcess or public digest cannot mint it. The parent binds actual worker input, complete stdout, executed source/resource pins and original transport identity; rechecks are retained. No fresh/native/model admission or new budget authority is issued by this token.

6. The explicit public-history frame/operation-view/carrier-mapping v2 claims complete original VERSIONED PUBLIC semantics plus separately authenticated private history. The original owner produces that public view. It does not claim the private subject/capsule/protocol can be reconstructed from public data, and opaque private proof bytes are not substituted for readable semantic facts. Typed capsule fragment disclosure remains exact owner/ref/file/raw-bound; full or unknown carrier aliases cannot bypass the positive disclosure boundary. New qualified compensation subject/proof/delivery versions are explicit, while old routes retain their original meanings. Original frozen requests and saved proofs are never upgraded or re-signed.

7. The committed default authority.v2 deliberately contains null installation inputs. The host rejects it before releasing a historical child; it is not a usable sample grant. Root must first bind actual finalized original R56 source/schema/interpreter and separate R52 producer authority, with fresh current-consumer policy/resource pins. A filled authority is a new versioned policy input, never evidence that a genuine positive replay already occurred. Fresh adoption v3 preparation belongs to the real R56 owner; the R57 historical/compensation integration rejects a fresh review-profile request instead of pretending to be that producer.

## Compatibility and limits

The original six formal record schemas, journal/index ownership, original operation bytes, Task/status/Acceptance/history/B-source, pending blocks, current-before effects and catalog-last contract remain under their existing owners. This adds an auxiliary historical/disclosure interpretation, not a new formal planning database. ADR-0050 same-policy exact verification and cross-policy anti-re-signing rules remain: the original policy is verified by its exact original owner, and the current consumer is separately bound; an old ticket does not become a proof of a new policy.

Codec delivery/version compatibility remains separate from adoption proof compatibility. The existing resource/work/input/transcript/model/fiscal limits are not raised or refunded by this ADR, nor is R23 native segmented70k changed. Root's separately authorized public-adoption context96 contract is not silently applied to compensation. No new native/model request, allocation, automatic retry or release follows from reading historical evidence. Old unknown and failed liabilities remain.

## Validation and status

Source presence and static route checks do not prove runtime success. At this documentation checkpoint, the default null authority is intentionally non-executable; genuine proof-v3 authentication, complete positive public-history disclosure and real compensation creation/review/commit remain unexecuted. The original thirteen-method compatibility scope, new focused mechanisms and genuine source-bound positives must be reported separately by Root, without relabelling mock/neutral tests as native qualification.

Story 2.6/2.7 prerequisites, real Windows fault/recovery evidence and original Build Step4/Step5 remain independently required for formal Story2.8 acceptance. No runtime verification, default-B activation, database isolation or protection from arbitrary external editors is granted. This proposed implementation record changes no frozen Intent or original AC1–5.
