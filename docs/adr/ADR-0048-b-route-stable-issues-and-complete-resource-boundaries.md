# ADR-0048：B 路线稳定问题账户及完整资源边界

## 状态

Proposed，2026-11-07。实现处于 Story 2.5 审核回环 3，正式故事审核及后续采纳仍待完成。此记录不启用默认 B 路线，也不授予发布或运行资格。

## 背景

原独立评审证明逐项绑定义务、来源与完整理由。直接把自由理由和整个分支正文用作修复计数键，会把措辞变化或合法的局部进展视为新问题。累计义务或选定原文上的问题可能没有可变的局部对象；把这种业务阻塞当作输入准备异常，不能表达既定的有界干净替换。

回环 2 的有界 wire 编码器也没有覆盖所有前置调用。输入准备和 selector 比较文件会先调用旧因子化与恢复函数，再进入最终门禁。仅最终序列化受限不能保护此前的分配。宿主清理中，日志、进程树终止或 Job 关闭失败还可能覆盖原超时或中断。

## 决策

1. 原八个语义 owner 及其传递依赖继续严格绑定。新增 `newrouge.b-route-issue-account.v1` 宿主账户适配器，仅在完整独立评审通过原 schema、分母、来源和 findings 对账后建立修复账户。该版本由冻结 runtime 规则中的适配器源码哈希激活，顶层状态和各次材料都显式绑定；历史规则继续使用历史问题身份。
2. 完整原评审、原问题理由、proposal 及 review 哈希继续保留。账户依据冻结来源、逻辑 owner、可辨识边界及重复多重性建立；模型不能自报修复权限。局部修复的历史来源必须经同槽位、同 lineage、较早已完成且已付的原生绑定回放核实。模糊分支保留各自阻塞项，不能通过猜测位置合并或扩大修复域。
3. 经宿主核实而无局部可变 owner 的业务问题，走原 replacement 预留与轮次控制，退休当前提案并仅保留不可变 scope 和已接受前缀。不得伪记三次未执行修复、修改选定原文、退款 unknown 或扩大原 slot/run/campaign 预算。身份、输入和执行错误继续失败关闭。
4. 准备输入、冻结输入复验、旧 core 因子化、selector 虚拟文件及最终 wire 构建共用一次请求内的资源账户。旧编码字节、字段、顺序和命名空间保持；在分配前预留工作，限额不提高。上下文变量只传递计量对象，退出时复位，不缓存证明或授予权威。原始 packet 在旧 compact 入口通过、在新完整 wire 保守门禁被拒绝的既有证据均保留。
5. 主异常与清理失败分别记录。stdin、终止、Job 关闭、wait 及诊断保存尽力执行；没有主异常时，清理失败仍失败关闭。保留实际拥有的进程句柄，不按未知或复用 PID 操作其他进程。新增源码边界逐 owner 精确绑定审阅后的 AST 或 raw 哈希，其他代码不获得通用豁免。
6. Windows 确定性 PR 门禁使用统一 selector，覆盖两个 profile 的生产 binding 协调器、协议、checkpoint、完整与 compact wire、截止、shutdown 和后代持管检查。CI 路径触发包含其真实 owner、测试和 fixture。所有模型回执均为明确合成数据；CI 无真实模型权限。新增 `b-route-runtime` 模式仅运行该离线门禁。

## 验证及限制

本轮首批 61 个定向方法及 7 个 Windows 实际管道方法已分别执行通过，源码屏障稳定。原 m4 回执锁定的 R5 源码与当前五类纯源码边界也已通过只读对照。它们不是新原生模型资格或 hosted CI 运行证明。后续9项多跳回放控制及两个profile完整协调器控制已分别通过，合计80个不同作者方法跨纪元通过；5项纯边界与277份旧清单哈希另计。完整协调器保留生产binding链，响应为合成high；本轮新增官方CLI验收调用为零，正式Step4/5仍待结束。

原 R22 producer、三名合格候选、原资格回执、失败历史、旧 unknown 和累计 79/290 占用保持原位。当前新增真实模型调用为零；服务端实际模型、推理和物理请求数仍未知。既有 stderr 单行资源与错误上报问题单独保留，不能宣称本轮已解决。
