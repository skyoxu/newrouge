# ADR-0044：B 路线元数据 journal 发布与前缀历史

- 日期：2026-11-07
- 范围：Story 2.5，审核循环 2，R2-B1 / R2-B2 / R2-B10
- 参考：[ADR-0041](ADR-0041-b-route-review-hardening-resource-and-metadata-boundaries.md)、[Story 2.5 规格](../../_bmad-output/implementation-artifacts/b-route/spec-2-5-independent-admission-bounded-selection.md)

## 问题

每个目标只使用一个确定命名的证据文件，无法同时保留连续出现的合法临时前缀 A 和 AB。两者虽然都是同一已认证后像的精确前缀，但要求早期证据 A 等于 AB 会阻断恢复。直接以独占创建方式向最终路径写入事务 JSON，也可能在尚未更改任何目标时因中断留下损坏的最终 journal。

缺少父级记账行、缺少 journal 或 journal 损坏，都不能证明模型请求未执行。本决策仅调整元数据发布，不新增请求、重试、预留 ID、候选生命周期、退款、预算授权或新的 `selected` / `completed` 资格。

## 权威与不变量

写入仍由原 coordinator 互斥锁管理。变更前，读取方必须依据可信的保留锚点、原始 run/model 字节镜像、record、源码身份代际、前像、父级提供的 selector 记账行及原 selector 状态约束，重建闭合的 `transaction.v1` 对象和精确操作。必须验证真实源码及其当前有效性、身份过渡闭包、现有有限命名空间，以及每个目标的精确前像／后像字节。文件名、哈希、调用方提供的 JSON 摘要或 PID 均不能单独构成授权。

允许的三种事务仍为 `prepare`、`reservation` 和 `unknown`。原调用 1..12、原 selector 失败证据、lineage、预算及源码历史均保持不变。预留事务只能保留原 `m4:dispatch:13`。协调恢复绝不发起模型请求。尚未结算的第十三次预留必须记为继续计费占用的终态 unknown；`released` 保持零，`retry_authorized` 为 false。

## 完整 journal 发布

对于精确规范化 journal 字节 J 及其原始 nonce N，新增发布路径仅为：

```
<kind>-publication-<N>-<sha256(J)>.part
<kind>-publication-<N>-<sha256(J)>.image
<kind>-publication-<N>-<sha256(J)>.pending
<kind>-transaction.json
```

1. 独占创建 `.part`，仅追加经认证的缺失后缀；对完整 J 执行 flush 和 fsync 后，以不覆盖目标的原子重命名发布为 `.image`。
2. 保留 `.image` 作为独立的完整恢复材料。独占创建 `.pending`，写入完整 J 并执行 flush / fsync，然后以不覆盖目标的原子重命名发布到最终 journal 路径。
3. 只有完整最终 journal 发布后，才能开始原有目标操作。每个目标在替换前必须立即重新核验。

独占发布使用 Windows `os.rename`，绝不替换已存在的目标。实现拒绝其他操作系统，不使用 POSIX 重命名覆盖语义。在原始字节 CAS 成功后，目标的前像到后像替换仍使用原 `os.replace` 操作。不删除任何存留的发布材料或历史文件。竞争目标或未知命名空间成员会阻断操作，并作为证据保留。

以上保证适用于使用原互斥锁的协作写入方遭遇进程中断时的恢复。文件 fsync 与原子重命名不代表硬件断电持久性保证，也不代表能够抵御绕过该锁的恶意写入方。

## 发布中断与精确镜像恢复

`reconcile(..., publication_images={kind: original_raw_bytes})` 可选择接收已存在发布来源证据的某一事务种类的原始完整规范化镜像。该镜像必须匹配现有的精确 nonce／完整原始字节摘要路径，以及所有已观察到的前缀；还必须独立通过完整的原权威、操作、身份过渡、命名空间及 CAS 校验。它不能创建新的事务身份、nonce 或请求。

原镜像材料仅在 selector owner 内部通过本次动作专用的 `ContextVar` 传递，绑定实际根路径及闭合的事务种类／原始 bytes，使用 `try/finally` 清空；其他根路径、线程或后续动作不能借用。这样原身份过渡校验的嵌套回调也能读到同一次提供的镜像材料。每次 `_journal` 仍独立执行完整认证，不共享验证结果、不跳过门禁，也不缓存或延迟原生见证。

原 coordinator 锁仍覆盖完整协调恢复动作。原 `verification_transaction` 只覆盖首次纯只读的来源、锚点、命名空间及身份过渡预检，必须在首次 journal 发布或目标变更前成功关闭并完成真实原生见证。后续校验同样不得跨越变更而延迟见证。若关闭见证失败，已存在的证据字节保持不变，不发布新 journal 或目标；事先建立的原锁文件不属于未知文件豁免。

| 观察到的状态 | 允许的操作 |
| --- | --- |
| 完整有效的最终 journal | 保留原文件；验证并仅补齐已获证明的目标操作。 |
| `.image`、`.part` 或 `.pending` 完整有效，但最终文件不存在 | 重建并认证 J；独占补齐发布，然后恢复目标操作。 |
| 仅有部分 `.part` / `.pending`，但独立保留了精确原始 J | 按现有 nonce、名称、原始字节哈希、前缀及原权威认证 J；追加缺失后缀并发布。 |
| 仅有部分材料，原始完整 J 不可得 | 以 `publication_material_incomplete_original_image_required` 阻断，保留全部字节。 |
| 提供的镜像使用其他 nonce／哈希，源码／record／记账行不兼容，或目标处于前后像以外的第三态 | 在任何恢复写入前拒绝。 |
| 已存在损坏的最终 journal | 以 `published_transaction_malformed_preserved` 阻断；保留损坏的最终文件及全部材料。绝不覆盖已发布名称。 |
| 遗留的部分 claim / intent 缺少原 journal／发布来源证据 | 保留原“未 journal 化”诊断及证据，不合成事务阶段。 |

首次部分材料可能缺少无法替代的身份字节。其摘要和前缀不能让宿主恢复这些字节。这是真实的输入缺失边界，不是零执行的证据，也不是重置阶段的许可。遗留的损坏最终发布同样属于已披露的保守边界；新的完整字节独占发布路径不会因这种进程中断而生成损坏的最终文件。

## 仅追加的前缀历史

在扩展任何已观察到的发布临时文件或目标操作临时文件前，必须先按下列路径保留观察到的精确前缀：

```
<kind>-history-<N>-<tag>-<length>-<sha256(prefix)>.bin
```

`tag` 中，`p` 表示首次完整材料，`j` 表示最终 journal 暂存，`oN` 表示某一精确操作索引。解析器从已认证的 journal 和操作推导预期完整字节串。它要求原始 nonce、已知标签／索引、有界且精确的长度、该推导前缀的精确哈希、普通单链接文件身份，以及属于这一特定快照前缀的实际字节。仅解析文件名绝不授予命名空间豁免。

后续更长前缀使用另一个不可变身份，因此 A 与 AB 均被保留。历史快照首次复制被中断时，只能追加其已知缺失后缀。绝不替换或截断已存在的完整快照。旧的确定命名证据 `<kind>-temporary-N.bin` 仍只按原精确后像前缀规则接受，绝不覆盖。任意文件、其他 nonce、无效哈希、外来字节及第三态目标仍会阻断操作。

## 验证合同

保留原有 29 个加固测试方法。元数据 fixture 仅显式模拟不可获得的上游保留源码／准入及身份过渡资格。新增 Windows 自有临时目录测试，对全部三个阶段执行真实 coordinator、journal 解析器、独占完整发布、目标原始字节 CAS、前缀历史及协调恢复。覆盖重复 journal／目标中断、证据复制中断、目标替换前后窗口、外来目标／nonce／前缀拒绝、缺失／损坏遗留材料及并发公共 prepare。

断言保留原调用 1..12 和原 model 字节，并检查最多一条继续计费占用的第十三次 selector 记账行、终态 unknown、禁止重试及零释放。合成资格 fixture 不构成原生准入或真实模型验收。实施方仅执行 AST／哈希检查；所有实际测试、集成及激活均由 Root 负责。本 ADR 不宣称 Story 完成、当前资格成立、新模型执行或正式采纳。
