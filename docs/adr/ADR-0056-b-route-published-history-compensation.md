# ADR-0056: Published-history verification for Cloud compensation

- Status: Accepted
- Date: 2026-11-12
- Scope: Story2.8 AC4, already published explicit adoption-review-v3 history only
- Authority: Explicit user direction to implement an equivalent or proportionately simplified Codex Cloud route against original AC4 after clean Astra max review. The independent reviewer agreed; no additional unapproved major tradeoff was identified. Acceptance of this design does not certify Story completion.

## Requirement and prior design

Original `epics.md:1135-1140` requires a new independently reviewed operation, current before images, exact original effects/scope/identity, and preservation of later edits, history, Task completion and B sources. It does not require executing a fixed historical Windows owner. ADR-0053 remains Proposed; its genuine original-owner/Job mechanism is one implemented verification route, not an additional business acceptance criterion.

ADR-0050's old proof semantics, complete public semantic denominator and prohibition on cross-policy re-signing remain. This decision adds a distinct already-published-history interpretation. It supersedes only the requirement to reexecute the original owner for that new interpretation; it neither upgrades an old proof nor changes what original-owner execution authentication proves.

## Decision

1. Select the new route explicitly with `newrouge.b-route-qualified-compensation-review-delivery.v3` before the first compensation build. Saved subject/proof versions select their own route for complete, reserve, commit and recovery. Unknown or mixed versions reject; there is no fallback after original authentication fails. Original delivery/subject/proof v1/v2 keep their meanings.
2. A current `PublishedHistoryVerification` factory reads the actual journal/index/intent/receipt/catalog. It requires complete publication lineage, no original marker, and the valid current relevant formal chain. `reserved` in the original allocation journal plus a complete durable commit is allowed; either field alone, a bare receipt or an orphan schema-valid plan is insufficient. The existing current owner separately protects relevant pending and full business scope.
3. Read the actual original embedded request, frozen/effects, original proof and all saved subject/prompt/schema/request/execution/output supports, capsule and retained binding. Recheck exact raw/canonical relationships and receipt-sealed proof/support identities. The binding-referenced unsealed request is a separate identity from the embedded sealed request and the new compensation request. Verify the original schema/check denominator and approved recorded protocol/runtime accounting without claiming to execute the old model or old owner.
4. Independently rebuild the complete recorded public subject from the original private subject, capsule, source, targets and allocations, ten inline fields, four retained-native fields, SourceSet, full public protection projection and selected-design history. Compare ordered/type-exact data with the original saved prompt. Preserve all original public semantic observations, including their historical limitations; do not delete protection or history to fit capacity.
5. This new result proves existing formal publication plus the specified saved byte/protocol/semantic correspondences. It does not prove that this process has executed the original owner, original interpreter, old Windows Job or original native producer. Old path/device/inode values are historical data; current safe path and actual root identity are separately bound. The new type is not added to `AUTHENTICATED_TYPES` and is not produced from an approved dictionary or a saved verifier report.
6. Only this branch drops the original interpreter installation, original absolute module location/physical root identity, Job reexecution, and historical debug-prerequisite cold reads that serve only that execution route. Required source/semantic bytes remain checked; no current input role becomes optional. The old execution route and its rejection conditions remain available unchanged.
7. New subject/proof/verdict/delivery/materials/roles/presentation/packet/frame/private-file versions are v3, with claim `complete_recorded_public_semantics_with_published_history_byte_verification`. Public frame/operation/carrier mapping are explicit v3 for this guarantee. New model instructions explicitly distinguish prior publication, recorded historical authentication statements and current byte verification. No old proof is re-signed or accepted through a mismatched reference version. Immutable profile objects select shared code; no runtime global replacement, parallel registry or duplicate protocol implementation.
8. Private references and action cache keys distinguish profile/claim. Handles bind the current root, verification policy and actual original pins and recheck them. New saved reviews can reconstruct their verified current-before formal view while their own exact effects apply; only the actual protocol-verified saved-input scope permits that view. Actual current drift remains checked by the existing commit observation owner, including factored private files. A saved before-view is never published as a replacement current state.
9. All existing current-before, old/current/new scope union, effects, Task join, cumulative obligations, status/Acceptance/history/B-source preservation, exact pending relation, unique successor, original journal/index, business locks and short writer checks remain. The new compensation still requires a new independent semantic execution with complete actual prompt/schema/request/output/runtime bindings and independent thread. The original saved23-check review and new history result cannot seal, reserve or apply a new compensation by themselves.
10. Keep170M local work, all codec/canonical/full-decode/exact checks,1MiB request,70k compensation gate, default96k total policy and existing paid/fiscal/unknown constraints. A new capacity profile or paid execution is not authorized by this ADR. Windows AC5 remains a separate original Story obligation, not a prerequisite for this read-only Cloud history path.
