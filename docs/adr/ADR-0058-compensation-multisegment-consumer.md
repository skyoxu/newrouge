# ADR-0058: Deterministic compensation multi-segment consumer

- Status: Accepted implementation scope; genuine model/fiscal and AC4 acceptance pending
- Date: 2026-11-12
- Scope: Epic2 Story2.8; extends ADR-0056 and supersedes ADR-0057 items4/7 for the new execution route
- Authority: Existing Epic2 authorization and explicit CLI/per-segment clarification; independent clean Astra max proportionality review

## Decision

The CLI derives a finite ordered dependency plan from the genuine current compensation owner. The model only returns business review verdicts. The new explicit stages are `review-segmented-prepare`, `review-segmented-execute` and `review-segmented-resume`; `review-complete` seals their separate proof. The offline preflight remains available. Existing one-turn delivery/proof versions keep their meaning.

The supported optimization covers the proved no-Task, same-plan revision family with one complete native source and no existing formal dependency uses. Its first closure contains all fourteen native fields, original source/control documents, original allocations and lineage, selection/history, identity rationale, authorization/limits and the full compensation request. It reviews cumulative obligations and existing formal semantic sources. The joint closure contains the complete remaining governance packet, exact original/current/new target projection metadata and the complete first verdict; it reviews the other seven checks, including target0. Native and source atoms are referenced only through their exact predecessor-reviewed values. Unsupported business families retain the complete closure rather than acquiring new Story prerequisites.

Host reconstruction verifies all original documents and complete ordered/type-exact packet equality. Only schema-typed native-to-formal owner/ID projection and exact four-field same-plan owner-revision rebinding are factored; business fields sharing those names are never normalized. All other old/current/new fields, lineage, provenance and retained-view metadata remain present in the joint closure. This does not assert that its model independently reread the predecessor's full native text.

New closure wire spelling changes only exact lowercase `sha256:` plus64hex strings into `~h64:` plus canonical unpadded URL-safe base64 of the same32bytes. Original `~` prefixes are escaped first. Keys and values restore in order; invalid markers and restored key collisions fail. Compact-v4 itself and old proofs are unchanged. Both the compact wire value and the restored original payload receive exact roundtrip verification within the same work/private-retention account. This is a transparent numeral spelling of opaque identifiers, not a summary, external dictionary, binary compression of business prose or replacement of semantic text with hashes.

Every admission measures the complete logical `prompt + output_schema` JSON RPC container using the existing counter, including JSON escaping, workspace prompt, schema and actual predecessor verdicts. Each input is at most70000 according to the existing measurement; input plus2000 headroom is at most96000 and the original1MiB gate remains. The2000 headroom is not a new output-size cap. Without official tokenizer tables, the existing UTF8 byte upper bound proves safety for byte-level tokenizers, but is not presented as exact token counts. The next request is rebuilt and measured before its reservation; oversized parent outputs stop continuation without another model call or clipping.

Each durable node binds exact request/schema/measurement, current source policy, stable intent, original reservation/outcome, independent high/no-tools runtime protocol, substantive check verdict and preceding results. Every thread and turn differs from all native ancestors and prior nodes. The explicit segmented proof binds every node and complete originals; it never reuses a one-turn request digest to represent several turns. Verification rederives the genuine source partition and full saved input bindings before minting a historical before-view.

Funding is a fixed optional installed original-owner adapter, not a new accounting pool or caller assertion. Without that genuine issuer, prepare and offline development remain possible while execution and fiscal-proof replay refuse with dependency_unavailable. Installation must bind actual applicable authorization, remaining finite plan budget and retained original unknowns. No new allowance, zero-use inference, Host ledger substitution or silent historical STOP release is introduced. Durable intent precedes reservation. Completed nodes replay without dispatch; a caller interruption after original ledger completion can finish local publication only from all original saved bytes and owner-confirmed outcome. Other pending/unknown intents stop without automatic reserve/retry/refund or a replacement operation ID.

## Evidence boundary

Synthetic DATA tests exercise the actual consumer, App Server protocol replay, proof/seal/history integration and failures with explicitly substituted model/business/budget factories. They do not qualify real execution, funding or old-owner identity. Actual preparation/capacity verification uses restored genuine materials, without a model or fiscal action. Historical DATA verification remains distinct from old owner execution authentication under proposed ADR-0053. Final AC4 still requires the new genuine review and applicable commit/recovery; AC5 and Story2.9/2.10 acceptance retain their own evidence requirements.
