# Story 2.6 frozen native reader profiles

This integration is implementation work. It does not establish Story 2.5 or
Story 2.6 acceptance, activate route B, dispatch a model, or authorize adoption.
The existing prepare/reserve, protection, Task, host review and scope gates stay
in force. A selected native marker alone is not sufficient evidence.

The read-only adapter supports three fixed source profiles:

| Profile | Preserved source | Required current binding |
| --- | --- | --- |
| Existing R10 | `Task/r10`, commit `dc245b3b3d14abd512879369b30692536dfac4fd` | Original continued-run checks, including retained failed-but-paid Cap history |
| R19 MVG synthesis recovery | `Task/r19`, commit `1d126b85b908ba1eea4b27ceeb8a9669a771e6f3` | Planner `mvg`, run `m4`, typed MVG source epoch with the original R10 predecessor and exact `m1` recovery reference |
| R22 selector recovery | `Task/r22`, commit `6d4ab1c3cba67bebe98f75c9462af613bf9d739a` | Planner `mvg`, run `m4`, typed selector epoch retaining exact R19/m1 and R10 predecessors, exact `s1` reference, and exactly thirteen completed calls |

The profile comes from the original state bytes and must agree with the closed
reader request and returned capture. Arbitrary caller source roots or commits
are rejected. Changing a capture digest does not allow an R10 proof to become
an R19 proof. The recovery record and complete historical/current authority are
still verified by the preserved native implementation, not by this table.

Before importing native code, a fresh isolated child independently verifies
the selected source's Git production membership, blob identities, allowed
checkout attributes and actual raw bytes. Source-only loading, module origins,
the exact metadata/describe process allowlist, dependency files/absence/globs,
source directory membership and closing pins all use that same profile. The
original R5 witness remains byte-bound; no original prepared data, paid receipt
or admission is re-signed.

Official `--describe` metadata uses a separate finite source-bound transport.
Its eight project source files have fixed raw hashes for the supported source
roots. An isolated `-I -S -B` child compiles the original runner script with its
original `__main__`, `__file__` and `--describe` semantics. Site startup and
third-party search roots are excluded from that metadata child. Unrelated
dependency caches are therefore not traversed or used as an absence gate.
Native proof paths retain their actual dependency and source-only checks.

The literal authenticated R5 verifier and its stdin stay unchanged. A compact
reader loader retrieves that literal from its pinned transition source instead
of embedding its large body in the Windows command line. The metadata envelope
adapts only the exact verifier-local audit callback, identified by its original
code object and globals: the finite authenticated describe command is presented
to that callback as its original logical argv. Other hooks receive actual argv
and register unchanged; arbitrary subprocesses or modified arguments gain no
exception. Source raw bytes and file identities close after describe execution.

The checked outer loader's exact reader raw digest is injected before reader
execution and inherited by every nested loader. A nested builder verifies the
disk still matches that inherited digest and embeds the same value; it cannot
authenticate a later reader revision. Actual capture requires this authenticated
context (or the parent checked loader's existing source digest). Ordinary
private command construction alone grants no capture authority.

The R19 source remains separate from this integration's planning schemas and
rules. Existing native proofs are replayed through their preserved source;
they are not reassembled with the current adoption code. The new reader's raw
identity also participates in adoption host-review policy, so a saved review
under an earlier reader cannot be relabelled current.

The R22 profile calls the original R22 selection, runtime, transition and
recovery verifiers. Its selector owner validates m1 against the genuine archived
R19 state, closes the trusted original capture and old twelve calls, and sends
call thirteen through the original full reserved-call/protocol verifier. C1's
R10 proof and C2/C3's R19 proofs retain their original bytes and identities.
The reader adds no alternate proof, anchor, historical-call or recovery waiver.

The original producer reads the fixed capture-02 helper, anchor, held-handle
exit receipt, stdout/stderr, source pins, V17 verifier bridge and terminal
controls. The existing read audit observes those actual reads for persistence
closing, alongside complete m1/s1 artifacts, current input files, absences,
globs, current registry and native checkpoint/handoff. R22's source closure
also pins R19 directory membership. R10 and R19 retain their original profiles.
The eight R22 describe source hashes were individually checked against the
existing fixed table; the source-only loaders and Windows argv bounds remain.

The dedicated `test_b_route_frozen_native_reader_r22.py` fixtures are synthetic.
They include source-bound unchanged R22 owner functions with toy codec/source
adapters and explicitly mocked authority boundaries. They do not establish
real capture eligibility. At this implementation checkpoint, only AST/static
inspection has been performed; Root owns test/native execution and the single
real completed read after the actual Story 2.5 gate closes. The old capture's
held OS0 says nothing about the current controller's OS exit or qualification.

Focused profile tests explicitly mock native/semantic success. Three transport
tests use only owned toy Python subprocesses and synthetic poisoned caches;
they preserve original fixture failures and do not touch real project caches.
Their positive fixtures
do not qualify the real `c4` or `m4`, prove a physical request count, or grant
formal adoption/readiness/runtime verification. Actual read-only native
interop and formal review remain subject to the root owner's sequencing and
the original prerequisites.
