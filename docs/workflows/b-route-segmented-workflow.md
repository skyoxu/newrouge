# Shared segmented workflow (opt-in v1)

Status: isolated implementation; not native activation or Story 2.5 acceptance.
The existing generation, synthesis, independent review, selection, receipts,
selected checkpoints, registry, and default protocols remain authoritative and
unchanged. This version never describes a segmented proof as the old proof that
put every original material in one request.

## Ownership and public boundary

| Owner | New file | Responsibility |
| --- | --- | --- |
| Core | `_b_route_segmented_workflow.py` | Frozen inventory, ordered dependency plan, four-phase scheduling, source citations, global coverage, fair selection, actual runner dispatch and protocol replay |
| Candidate products | `_b_route_segmented_candidates.py` | Generated object slots, dependency-closed synthesis, complete host business validation and new segmented candidate proof |
| New run authority | `_b_route_segmented_runtime.py` | Genuine current 3A/host preparation, reviewed source catalog, opt-in birth and original epoch/funding witnesses |

| Tests | `tests/test_b_route_segmented_workflow.py` and owner tests | Explicit synthetic native boundary; real new codec/closure/renderer/journal checks |

All paths above are under `scripts/python/`. The owning specification is this
file. No legacy owner is changed to opt in. Root alone runs integration tests,
native operations, and models. Production imports, policy capture, and tests wait
for the common source barrier.

The protocol is `newrouge.b-route-segmented-workflow.v1`. Separate closed schemas
identify the manifest, plan, envelope, response, verified result, and completion.
Every request and continuation binds this version and the same plan digest.
Unknown schema versions cannot fall through to legacy dispatch.

Core APIs are `freeze_manifest`, `build_plan`, `validate_plan`,
`require_segmented_run`, `execute_workflow`, `verify_response`,
`validate_verified_result`, `phase_instruction`, and `output_schema`.
`execute_workflow` opens the journal's original-owner session and dispatches all
four phases through `run_isolated_model`. Each completion is replayed by
`_planning_execution_binding.validate_execution(require_runtime=True,
expected_reasoning_effort='high')`; return code, a model-provided boolean, or a
handwritten receipt cannot substitute for this replay.

## Frozen inventory and semantic partition

The host inventory contains every original source and original candidate needed
by the governed stage, exact original versions, raw SHA-256, byte length, and
case-exact protected path. References are rejected for sensitive roles before
filesystem access. Reads reject aliases and reparse paths. An original material
is divided into a contiguous, complete ordered partition. Each segment binds its
material, original byte offsets, original slice SHA, ordinal, and predecessor
slice digest (the first binds the complete original material digest). UTF-8
boundaries must be valid. Global constraints are indivisible original materials
and are included in full in every request.

Partition boundaries, the complete obligation/ID/edge catalog, candidate mapping,
and mandatory dependency closures must come from the frozen governed input
owner. A mechanically valid partition is not evidence that its boundaries or
semantic catalog are correct. Fresh independent reviews must explicitly review
omissions, boundaries, cross-segment effects, order, shared definitions,
requirements, non-Flow effects, and cumulative preservation. Discovery of an
unlisted dependency, omitted obligation, or untested interaction blocks this
plan. It requires an explicitly reviewed successor plan, not an in-place edit or
automatic paid retry.

The host checks full byte coverage, no duplicate/missing/out-of-order segments,
canonical identities, obligation coverage, dependency closure, and citation
ranges. Derived extraction/decision records are explicitly marked as derived;
they are not lossless original documents and cannot replace a required original
semantic closure.

## Four phases and evidence flow

1. **Generation** reads bounded original segments plus all global constraints and
   emits source-cited obligations, decisions, dependencies, and unresolved items.
2. **Synthesis** consumes dependency-closed prior decisions. It does not reload a
   bag containing all original source and all drafts. Any original material it
   needs is an explicit mandatory closure, counted in the same final request.
3. **Independent review** uses a separate fresh ephemeral high/no-tools turn and
   the complete related original byte ranges across segment boundaries. It
   reviews the complete obligation denominator, dependencies, interactions,
   source support, and preservation. A summary-only review cannot approve it.
4. **Selection** first performs equal candidate-by-dimension joint reviews over
   the same source closures. The final bounded decision sees all relevant
   decisions, dependencies, interactions, unresolved items, and the complete
   fixed global constraints. Its additional original segments are derived from
   the mandatory host dependency closure; they may be empty only when every
   needed meaning and interaction has already had a complete original joint
   review. The final request does not automatically reconstruct every source or
   draft. An indivisible mandatory closure that cannot fit blocks the workflow.

Every turn is a fresh ephemeral invocation with no conversation history, no
tools, and no cross-request model memory. Dependency records and exact original
citations are explicit request data. A separate review turn is independent in
execution; it is not a claim of a physically distinct model. Requested and
returned runtime reasoning configuration must be high; physical/provider model
identity and actual provider reasoning strength remain unknown.

Native candidate generation/admission and original selected checkpoint
publication still require their existing native owners. This engine's artifacts
alone grant neither. A new native born-contract producer and native consumer
must bind the protocol before generation. `require_segmented_run` fails before
mutation when that named owner is unavailable. A state flag or retrospective
attachment to old c4/m4 is insufficient.

## Capacity and fairness

The input ceiling is **70,000 tokens of the final serialized model request**,
including instruction, schema, common constraints, segment bodies/references,
derived predecessors, and the official workspace wrapper. Output is reserved
separately. Input plus output reserve must be at most the existing 96,000 context
limit. Use the original conservative token measurement owner; caller-provided
counts are not authority. Measure once on the actual immutable final wrapper and
check that exact wrapper again before dispatch. No truncation, omitted common
constraint, hidden side input, or implicit previous conversation is allowed.

Candidate identity, original snapshot, order, blind label, review dimensions,
boundaries, and evidence denominator are fixed before comparison. Every panel
contains every original candidate, the same dimensions and source obligation
closure, and equal verification opportunities. The host rejects missing or
duplicate candidate/dimension cells. Final adjudication covers all panels and
cross-panel interactions and chooses exactly one fixed original candidate. It
does not combine candidates, add scalar scores, or call a single-elimination
tournament a global decision. Small-fit controls and candidate/order/partition
bias cases are required before activation.

## Durability, budget, and continuation

The original `_mvg_capability_recovery.operation_lock`, run
`_mvg_capability_checkpoint.coordinator_lock`, and short original registry lock
remain the only mutex/epoch system. No metadata lock spans model execution. The
new auxiliary journal uses the original apply-journal owner for multi-target
durability; it is not a second recovery registry or accounting authority.

Before the first request, reserve the entire finite worst-case schedule against
the real native and campaign owners. One node permits one paid invocation; v1
has no automatic retry. Native ceilings remain Capability 96 / MVG 192, original
lineage limits remain 64, campaign remains 290, and released remains zero. All
actual previous paid/unknown liabilities must be read fresh. There is no top-up or new run that
resets spent capacity. Planned count is the complete number of request nodes,
including all source extractions, closure syntheses, independent reviews,
candidate-equal joint panels, and global adjudication. A plan larger than the
remaining real budget is rejected before dispatch.

Persist immutable original request bytes/hash, schema, output bytes/hash,
captured OS execution, original runner receipt and protocol, parent result
digests, and original ledger reservation. Claim before dispatch; settle after
real replay. Missing, duplicated, reordered, stale, mixed-identity, unknown, or
partially published artifacts stop progress. Unknown remains charged and blocks
another dispatch. No lock file or claim is unlinked to enable a retry. A known
failed request remains audit and cannot silently acquire another node ID.

Successful continuation replays exact completed nodes and closes fresh original
source/configuration/epoch/revocation controls. It never trusts a persisted
`verified: true` field. Source/configuration drift, unrelated pending activity,
or a changed original proof blocks; it is not masked by auxiliary journal state.

## Required offline evidence and remaining gate

Before activation, cover cross-conflicts, omissions, boundary breaks, missing/
duplicate/order/mixed/stale artifacts, unknown/interruption, indivisible global
and dependency capacity failures, small-fit equivalence, candidate symmetry,
order/partition bias, complete request hashes, genuine protocol rejection, and
original budget/lock behavior. Synthetic native seams must be labelled and must
not be reported as real semantic or native acceptance.

This isolated implementation does not alter old requests or receipts, dispatch
real models, activate a new native profile, grant readiness/default B/runtime
acceptance, or complete Story 2.5. Root must review the full implementation,
genuine original-owner born binding, semantic/native consumer seams, and current
worst-case campaign funding before any real activation.

## Candidate production contract

`candidate_contract=None` is decision analysis over already frozen snapshots. It
does not produce a new candidate-generation proof. Production instead uses
`newrouge.b-route-segmented-candidate-contract.v1`: the genuine current host
input identity, complete ordered object slots, and mandatory final object
closure. Each slot fixes its candidate label, original business collection,
generation node, synthesis node, source obligations, and prerequisite slots.
Candidate identities are fixed at birth; generated content is not a
retrospectively declared input snapshot. No preexisting candidate body can be
substituted for this production path.

G emits complete typed business objects in `candidate_pieces`, with original
source citations. Each `value_json` preserves its complete JSON value; it is new
generated business data, not lossless source. Every assigned slot is present
exactly once. S sees only its candidate's actual original generation pieces in
the host-derived dependency closure. It binds those piece digests and explains
every revision. A preservation review receives the complete original G value
whenever S changed it, alongside the complete S value and related original
source. A summary or change explanation cannot substitute for that original.

The host concatenates ordered collection slots and retains the singleton source
identity to form the full candidate. It invokes the original complete content
schema and `candidate.check_sources`, `check_owners`, `check_graph`,
`check_relations`, and implementation-reference checks. It never creates fake
old `model_draft` provenance to bypass the old draft chain. The new original
candidate identity binds full content and exact paid synthesis results. Its
original bytes are deterministically recoverable from immutable original
fragment strings; selection cannot edit those strings, mix candidates, or
generate a replacement.

The candidate owner derives actual logical/Flow/Requirement dependencies from
full objects, extends the source-declared closure with those edges, and provides
complete related objects for independent review. Every original slot receives
an exact digest-bound supported review. Global host checks retain all object
IDs, source membership, edges, accounting and preservation. Comparative
selection begins only after every object of every candidate has a complete
independent review. Final required closures remain full originals. An empty
final body list is permitted only after the actual complete review prefix has
been validated, never by a caller's `final` boolean alone.

G/S/R requests are candidate-private: parents, slots, generated values,
revisions, and product views belong to that one candidate. Only comparative
selection sees all fixed blind candidates together. An output label does not
excuse another candidate's private data leaking into a generating request.
Every completed turn has distinct actual returned thread and turn IDs, excluding
genuine upstream 3A receipt identities. A new prompt in a known thread is
rejected even if its one-turn protocol is otherwise valid.

The new proof is `newrouge.b-route-segmented-candidate-proof.v1`. It claims
`new_segmented_candidate_qualified`, binds all paid results and full candidate
identities, and leaves legacy native admission, formal adoption, readiness and
default activation false. Catalogs, slots, final closures and plans must match
the genuinely audited planning source contract. A caller catalog or generation
extraction cannot invent its own mandatory denominator.

Artifact and executing source roots are distinct. Source policy hashes and the
runner executable come from the actually loaded module tree. Governed evidence,
native ledger, epoch store and artifacts remain under the explicit artifact
root. An isolated newer source tree is never represented as the artifact root's
older code.

The engine fixes the official `codex_isolated_model_runner.py` in that executing
source tree; there is no caller runner override. The new runtime's scoped
source-only launcher binds the real bootstrap, transitive source bytes and
dependency roots for describe and execution. A `-B` flag alone is not a claim
that unchecked existing bytecode was excluded. Host execution distinguishes
original logical runner arguments from actual transport arguments; both are
retained with source provenance. The engine changes no model/speed/Fast setting
or authentication configuration. It requires actual returned high configuration
and reports provider reasoning strength and physical model identity as unknown.

`verify_proof` uses a fresh complete authority capture and the original journal's
explicit read-only session. Pending publication, unknown requests or missing
completion block verification; it cannot automatically repair them. A cold
snapshot replays each original paid protocol once and returns genuine in-memory
tokens for subsequent same-action local closure. A copied JSON `verified` flag
cannot replace those tokens.

Same-campaign migration also retains actual previous usage of each native
profile and its original time/lineage pools. Starting a new run ID does not
reopen 96/192 calls or restart the clock. The real funding witness derives old
calls and unknown liabilities from original controls and ledgers. A pure plan
contains only `native_limit`, `campaign_limit`, `released`, and
`worst_case_calls`; it contains no caller-provided or hardcoded amount spent.
Genuine pre-plan, born and every-action funding/CAS guards enforce actual
remaining capacity, including charges accrued after plan construction.

Every paid claim also binds a permanent input-only archive outside the model
workspace: exactly the original `prompt.txt`, `input.json` and
`output-schema.json` under fixed sibling `i/`, with an external
`input-archive.json` manifest. Cold verification calls the unchanged official
`workspace_payload` on this archive and verifies the actual workspace's three
input byte strings match it. It never moves or hides output sidecars. Real
wrapper/request hash, measured input, schema, original paths, official runner,
logical timeout/one-call argv and actual source transport must match the original
paid reservation, resolved from the real registry, ledger and permanent claim.
Another genuine high/no-tools receipt cannot be relabeled as this request.

Model input uses the fixed opt-in wire schema
`newrouge.b-route-segmented-wire-input.v1`, with the existing compact-literal
v2 codec. The outer object has exactly `schema_version`, `codec`,
`original_json_raw_digest` and `literal`. Its self-contained string/subtree
tables reconstruct the complete
ordered logical envelope; no original source, G/S body, business schema,
interaction member, review record or fair-candidate denominator is projected
away. The wire binds the UTF-8 SHA-256 of the original canonical logical JSON.
Strict canonical decoding and the whole logical hash precede the unchanged
source-envelope and business checks. This is a new physical input representation,
not a claim that its request hash matches a former expanded JSON request.

The request owner adds the complete fixed decoder explanation exactly once to
the original phase instruction. Both explanation and wire JSON enter the
unchanged official workspace serializer and final-wrapper measurement: input
remains at most 70,000 tokens and input plus original output reserve at most
96,000. The permanent input archive retains the three actual wire input files;
paid claims and official receipt replay bind those physical bytes. Host readers
use the fixed request-owner decoder to obtain the complete logical envelope.
Unknown sidecars remain rejected by the original exact execution closure.
The compact codec's actual executing source bytes are included in source policy.

Review uses host-derived undirected semantic interaction domains, not outgoing
dependencies alone: `F1 -> C <- F2` requires F1, C and F2 together, with every
related original source, in a real independent review request. An exact
`joint_checks` witness binds all member digests, interactions and source
obligations. Separate supported slot checks cannot discharge that joint
denominator. Truly unrelated definitions remain separable. Selection/final
qualification require every actual domain's genuine joint review; a closure
over 70k blocks rather than being certified in disconnected pieces.
