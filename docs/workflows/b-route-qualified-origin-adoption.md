This is an offline implementation draft for a finite dual-root adoption entry.
No test, original verifier, CLI, model, claim or funding operation was executed

## Roots and proof ownership

The only origin profile is `r22-m4-nx-original.v1`. Its trusted Task location,
original `nx` root, selected `mvg/m4` run, handoff, complete V15 synthetic source
and three existing qualification receipts are fixed in
`scripts/python/_b_route_qualified_origin.py`. No request may supply an origin
root. The bridge must remain installed in the retained Task checkout; an
arbitrary copied installation cannot derive a new trusted origin from cwd.

The original frozen reader is invoked against the real original root under its
original activity/coordinator owners. Original input, policy, raw proof,
prepared identity and source closure are verified there without rewriting them.
The target is a separate root, with absent or empty Task context, no published
planning namespace and exactly the complete original synthetic file registered
in its source set. Retained producer checkouts are not valid target roots.

`origin-prepare` is a zero-model metadata stage of `b_route_adoption.py`. It
requires `--root`, `--operation-id` and explicit `--origin-profile`; it does not
accept `--request`. Root alone may execute it under a separately reviewed finite
original-reader child profile. It creates an operation-bound derived capsule,
returns its actual raw-bound reference and preserves conflicting/partial files.
Its result is not a new qualification or approval.

The capsule retains complete selected content, source bytes, original capture
identities and file/member maps. It does not contain the original full prepared
or protection blobs. The original synthetic source manifest and block ledger
are copied byte-for-byte, create-once, at their original relative locators in
the target so the unchanged formal source owner can resolve them. These two
documents contain only this synthetic case and its technical provenance. Their
raw digests are fixed; this is not relocation or re-signing of the native proof.
They join the target snapshot and frozen authority closure.

## Versioned host admission

The request and auxiliary operation envelope use `.v2`, with the existing
material fields plus fixed `origin_profile`. `handoff_ref` and `review_ref` both
bind the actual derived capsule. Only a whole new plan is admitted: plan mode
`new`, binding mode `none`, no Task joins, all requirement/Flow mappings allocated,
and no arbitrary authority or lineage references. Target templates retain all
original candidate semantics through the existing exact typed projection.
Use the fixed `RATIONALE` exported by the adapter for host mapping rationale;
unknown added host prose is rejected rather than classified as safe text.

The private host subject is `.v2` and binds the complete original prepared
identity, current target protection and target dependency observations. Its
model lane is a separate positive renderer containing only the complete V15
source, complete selected semantic content, exact target before/after, typed
allocations and technical identities/digests. Current original Task definitions,
Acceptance/history and full machine proof blobs are not serialized. Unknown
authority text, foreign source evidence or extra host strings block rendering.
If this finite projection cannot preserve an obligation, admission fails closed.

A fresh host semantic review is required; v2 has no inherited mechanical
approval. Prompt, strict verdict, execution receipt, fresh thread/turn evidence,
high reasoning and no-tools checks remain with their original owner. The bridge
does not dispatch that review or create funding authority. Runtime configuration
and provider actual model/physical request identity remain distinct.

Public prepare/reserve/apply/verify/publish/read still use the existing services.
Commit observations retain original-root absolute files/member maps separately
from target dependencies. The existing commit-intent schema already supports
these absolute immutable observations and target-only owned before/after writes;
it is unchanged. No target before/after exception permits mutation of origin
evidence. Current target protection is required in addition to original proof.

## Opt-in readable semantic review v3

Request-level `review_profile: expanded-semantics.v3` selects a new private
subject/model view/verdict/proof v3. It does not alter native Material or Plan v1.
An absent profile keeps the v2 renderer, prompt, checks and proof version. Unknown
or mixed versions fail closed; historical proofs remain bound to their original
source/policy epoch and are never re-signed as current v3 approval.

The v3 view contains a raw-bound actual registered SourceSet, separate complete
Task/cumulative/frozen-A/legacy observations and protected-file metadata, never
production source bodies, private protocols or credentials. Original collector
authorization/limits remain literal false observations, not policy approval.
Policy switch_boundary is reviewed proposed content, not runtime activation;
empty references do not confer A qualification and empty operation lists have no
implemented wildcard or deny-all meaning (record-contract).

The existing ten inline Plan fields and four fields retained in the required
native_candidate_ref are shown with explicit storage correspondence. Original
retained literals and derived host-identity interpretations are distinct. Formal
bundle read does not automatically expand that reference; availability of the
original verified native reference is required when full retained semantics are
needed. No JSON-in-string or private Plan v1 extension is introduced.

All existing semantic check IDs/denominators and omission/conflict blocking stay.
The model reviews complete visible source/current selection/target semantics and
every actual lineage or unprovided semantic dependency. It does not authenticate
private origin signatures. Host native/capsule/protection/currentness and exact
protocol/high/no-tools verification remain mandatory machine responsibilities.
Native draft-selected wording remains literal. The view includes authenticated
ordered draft identities, the complete related selected launch/message profile
and independent-observer choices, with current-command correspondence; it does
not expose whole draft bodies or claim earlier approval. A new Plan's null prior
Plan is not proof of a prior draft; unseen semantic dependencies remain blocking.

A known blocked review is immutable evidence, not an approved host review. A
changed consumer policy cannot overwrite its saved subject or retained binding.
Any future new operation/review must use genuine owner-issued current bindings,
new immutable paths and a Root evidence link to the old known rejection, while
preserving old bytes/occupancy. Merely changing review_profile cannot revive an
old source epoch. Source/reader provenance and current native admission must be
actually satisfied; no fresh native/model run is authorized by this description.
