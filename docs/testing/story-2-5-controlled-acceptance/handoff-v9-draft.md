# Reward handoff test

Each scenario has one fixed reward R, one process at most, serial calls, and its own initially empty durable journal J. Restart preserves J; scenarios never share it. The only record is Commit(R), an atomic durable reward grant AND logical map return. J is either [] or [Commit(R)]; no partial state exists. Rendering MapReady is not another grant or return. Storage succeeds except for the specified process crashes. UI starts Idle on each process launch and changes only during an API call.

accept(R,call_id): if J is empty append Commit(R) once; otherwise retain the exact journal. Then expose MapReady and complete. First and repeated accept both finish without another user action.

resume(R,call_id): with Commit(R), expose MapReady; with empty J, expose Idle. Never append anything. This is the recovery handoff after restart, without another user action.

The external harness records one ordered sequence of CallStart, Crash, CallComplete, ObservationComplete, ForceTerminate, ProcessExited, StartProcess and ProcessStarted. Every API call uses a fresh call_id. A non-crashing call must emit exactly one matching CallComplete with ui_state=Idle or MapReady, then allow independent reads of actual UI and complete J and matching ObservationComplete, all within 10000ms of CallStart on the harness monotonic clock. Check identity, one completion, time, expected UI, exact journal and agreement with reported ui_state before ObservationComplete. Missing, late, duplicate or wrong-call completion or observations fail. No eligibility wait postpones the deadline; a later crash never erases failure. After CallComplete, UI and J stay unchanged until the next call or crash.

The only within-call fault hooks are immediately before and immediately after the missing Commit append in accept. A hook force-terminates the process, records Crash and ends that call without CallComplete. Before-append leaves J empty; after-append leaves one Commit. Every restart uses the unchanged J: if live after successful ObservationComplete, ForceTerminate is the next harness action; if crashed, do not kill again. Observe ProcessExited, issue StartProcess, then observe ProcessStarted before any API call. Exit after ForceTerminate/Crash and startup after StartProcess each have a separate 10000ms harness-clock deadline; timeout fails. No graceful shutdown, journal reset, overlapping process or other restart procedure is allowed.

Run separate normal and post-completion-crash tests for accept/empty, accept/committed, resume/empty and resume/committed. Establish committed prefixes by normal accept plus ObservationComplete followed by the restart procedure. In each post-completion test, ForceTerminate is the next harness action after the target ObservationComplete; record Crash for that termination, then continue the restart procedure at ProcessExited without a second kill. Separately inject each append hook once, starting empty. After every target crash, restart, disable within-call hooks, complete resume and its observations, then perform exactly two further restart/resume cycles using the same procedure and journal. Preparation restarts do not start this target recovery tail. Also run exactly two accepts in one live process from empty with hooks disabled: the second is the next harness action after the first ObservationComplete. Each call must meet its own observations/deadline; the second preserves the exact journal. Invariants hold at every observed prefix.

The reward controller owns J and UI; the harness owns the external event sequence and independent observations. The reward-to-map Flow has entry accept or recovery resume, a guard reading J, execution performing the specified append or no-write recovery, and finalization exposing the required UI then completing. First accept grants and returns; repeated accept preserves Commit, while resume restores MapReady or Idle according to J. Its crash branch hands the unchanged durable state to restarted resume. Reference both resources J and the map UI in the plan. Planning does not claim this game Flow has run.
