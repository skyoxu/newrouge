Cumulative MVG scope

如何解读 Cumulative MVG scope

这里展示的是累计的 MVG（Minimum Viable Gameplay）验收范围。每个 manifest 是一份版本化的回归清单，描述一组必须一起验证的完整流程，而不是某个单独 GDD 版本的映射结果。

  • Flow：一个可观察的完整行为，例如 New Run 到 Map、Map 节点进入所属流程、Continue/Resume，或 Combat 到 Reward 再返回。
  • Task IDs：构成该流程的任务集合。它们用于追溯范围，但不表示每个任务都会单独执行一次。
  • Handoff：流程中两个任务或边界之间的交接约束，包含 producer、consumer、owner、契约和验证测试。
  • Outcome：该流程要证明的行为结果；它不是测试名称，也不是 GDD 版本说明。
  • Evidence：自动化测试、运行结果、manifest 哈希和当前 main revision。状态为 not_verified 时，只代表当前 revision 尚未取得匹配运行证据。

这个板块与上面的 GDD version 下拉框相互独立：GDD version 回答“需求来自哪个 GDD 版本”，MVG scope 回答“当前 main 需要累计验证哪些可玩流程及任务交接”。

MVG manifests define cumulative flows and handoffs independently of the selected GDD version.
