# 验证范围、证据与恢复合同

## 两层职责与证明等级

Task 局部自检覆盖其领域规则、接口、绑定和受影响局部行为；Flow 集成在相关实施齐备后验证真实输入、跨层交接、状态变更与最终结果。Chapter7 只收口目标 UI slice，不等全游戏，也不重复建立已实现且已验证的同义义务。

结构检查、业务语义审阅、编译／类型检查、静态接线、场景方法调用、真实引擎输入、人工视觉／手感是不同证据。planned、关系存在、未运行、跳过和空报告不能记为运行通过；局部 PASS 不自动推出 Flow PASS。Flow 全部当前必需义务满足才完成，里程碑另按累计要求判断。

真实对象存在后补类型、编译、绑定及引擎检查；不让 planned 提前假装实现，也不因未实现而允许缺失实施定义。Domain／Contracts 保持 BCL-only，Core xUnit 与 Godot GdUnit4 复用既有框架和质量底线，人工义务不由机器报告替代。

## 传递影响和三类义务

变更共享规则、状态、命令、契约、适配、场景资源或测试基础设施时，登记全部必要传递影响，包含未实现 Flow。范围由有效来源与当前采纳计划确定，绑定当前累计基线和义务；不能选旧 manifest 遗漏本次要求。

| 义务类别 | 必须执行／保留 | 完成判定 |
| --- | --- | --- |
| 既有受影响回归 | 完整执行既有必需测试；本次改坏、无法启动同样须修复并验证 | 不得改 planned／移出范围；旧回归通过也不代表新增义务通过 |
| 本次新增或未完成义务 | 保留实施与验证责任，未齐时 pending／blocked | 阻断本次范围完成，不借已有代码可运行忽略新义务 |
| 范围外未来义务 | 登记影响，更新相关定义／绑定和后续责任 | 不要求提前实现，不宣称已验，不从后续累计验收遗漏 |

同一 Flow 可同时含既有及新增义务。未知映射保守扩大到适用累计范围，仍三分类，不将所有未来 planned 当作可执行回归。无法确认本次必需义务全部满足时不得宣称完成。合法范围调整仍保留差异及累计防削弱，不通过失败重分类换绿。

可保守执行更大范围。若实现选择性运行，真实执行器须消费请求范围，输出实际执行、待完成、人工义务和覆盖，绑定当前计划／manifest／整合快照；仅改变排序的 recommend 不能称选择性回归。critical／partial／单 Flow 结果不能命名为整个里程碑 full-MVG。

## 验证时机与资源复用

| 时机 | 应做 | 不默认重做 |
| --- | --- | --- |
| 来源／规划变化 | 相关语义、覆盖、身份、结构及必要独立审阅 | 未变来源及有效已提交采纳的全量重生成 |
| 有意义 Task 实现单元 | 领域／适配／绑定的局部检查与必要测试 | 每按钮／节点／编辑全 MVG |
| Task 完成／恢复 | 当前 Acceptance、readiness、适用义务及既有 Chapter6 检查 | 全局 Knowledge 重建或为非 Flow 造 Flow |
| 纯实现缺陷 | 必要映射及就绪、自检和适用回归 | 整套3A／3B重规划 |
| 目标 Flow 与 UI 齐备 | 全部当前必需集成及人工义务 | 无依据全项目扩大 |
| 有意义共享变更批次 | 全影响登记，既有回归、本次新增及未来责任分别处置 | 每保存立即验全库，提前实现范围外 Flow |
| 累计里程碑收尾 | 当前累计必测及组合测试的同一整合快照证据 | 拼接不一致快照或将局部绿色升格 |

构建／预热可共享；相同测试结果仅在相关输入、整合快照、测试身份和验证语义均匹配时供多个 Flow 引用，各测试仍隔离可变运行状态。

## 三种稳定性必须分别验证

1. 规划稳定：相同有效采纳输入恢复时复用已审阅计划、身份与拆分；显式重规划有差异和身份对齐。
2. 应用幂等：持久操作身份与内容绑定，同身份同内容无重复 Task／delta／覆盖；同身份异内容报冲突。
3. 证据有效：输入与规则匹配才复用，非仅 Git HEAD／Task ID／文件名／单一正文 hash。相关来源、采纳、Task、契约、绑定、规则、依赖及影响结果的工具链／环境纳入身份。

当前 ADR-0039 使用完整单项 Capability 规范化内容哈希匹配完成项，再验证原冻结 proof、当前相关依赖和累计 delta，写独立 adoption receipt；匹配键不等于全部证据有效性。MVG 新执行不恢复候选／修复／检查／评选中间态，持久预算不重置；clear／reopen 撤销后的项及后继不得复活。Capability 显式 --resume-evidence 与多产物应用 journal 各按自身协议恢复，不泛化为中间态复用许可。

多产物写入有持久记录与恢复点，中断先核对已写结果和所有依赖；后编辑、未知版本、证据损坏及不一致状态不能视为未变化而盲重放。未一致提交的 B 输入在真实消费者处阻断，不能只依赖 Agent 自报完成。具体提交／恢复协议留给架构，不把已有逐文件 replace 当多文件事务。

## 原始验收场景的使用

SPEC 采纳的 PRD addendum 中 AC-BR-01–23 是必读验收目录，原身份不变。覆盖零 Task 正式规划、独立遗漏审计、循环与四部分、多对多、planned 身份、幂等／中断／后编辑、所有入口拒绝、相关与无关失效、局部自检、三类义务、真实输入断绑定、UI 复用、存量保护、旧 done 新义务、格式迁移、同快照、合法非 Flow、共享变更 A／B 反例及局部修复。

AC-BR-20 要求可追溯的阶段耗时、模型调用、复用、重复测试与返工记录；按用户最新方向用于观察重复工作和失败开销，不要求比 A 快、成本下降或固定 Task 时间。无进展止损留原因，成功且输入未变的上游阶段不因下游失败重付执行。

另保留集成 owner 自依赖反例：只有集成测试责任的 owner 不被迫先完成自身业务实现，不按 owner 数伪造生产接口；producer／consumer／owner 原有适用差异继续覆盖。
