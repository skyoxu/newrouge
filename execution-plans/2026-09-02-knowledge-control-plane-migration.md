- Chapter 4 pilot finding: the original 12-candidate bundle was retrieval-valid but not freeze-ready. Every returned candidate was runtime/overlay/ADR/contract material; the authoritative `docs/prd/PRD-NEWROUGE-GAME-0001.md` existed in the trusted snapshot but was absent. Because Chapter 4 requires both `product-intent` and `architecture-authority`, accepting overlay material as `product-intent` would be a semantic false-positive and would violate the consumer-owned decision contract.
- Chapter 4 adapter repair: required-context supplementation remains in the consumer adapter rather than the global Locator. `prepare_knowledge_context.py` preserves explicit scope identifiers such as `PRD-...`, runs bounded required-class supplement queries, deduplicates candidates, and records `retrieval_context_classes` only as retrieval evidence. The product-intent route now includes a policy-declared canonical path template `docs/prd/{scope}.md`, so the scoped PRD can be found deterministically without weakening Locator thresholds or relying on natural-language ranking. A targeted regression then exposed a separate attribution defect: an exact-path Locator query can legitimately return both the exact PRD and files whose content references that PRD path. The adapter previously assigned the query's context class to every returned candidate, which incorrectly tagged an Overlay as `product-intent`. Exact-path query-plan entries now carry an attribution path, and only a candidate whose `path` exactly equals that rendered canonical path inherits the exact-path context-class label. Related candidates may still be merged into the shadow bundle, but they do not inherit the authority class merely because the Locator returned them from the same query.
