# Finite historical migration verifier: decision proposal

Status: Awaiting the user's explicit decision. This file does not install an owner or authorize execution. Applies only to Epic2 Story2.8's actual NativeV15Origin03 history and its new NativeV15Origin03Compensation01 operation. No other historical family, general platform port or Epic3-5 work is proposed.

## Problem and reviewed choice

The existing historical host deliberately requires an installed original R56/R52 owner, original interpreter/command identities, actual fixed Windows source paths and the original target's physical identity. The migrated null authority was deliberately excluded from the original machine's populated uncommitted installation. Filling it with cloud facts would not make the unchanged old verifier accept this copied target. A different Windows executor alone is also insufficient: physical target IDs, source paths and old interpreter/policy predicates remain.

The old worker also requires Windows Job ownership before any project code is released. There is no demonstrated delegated equivalent in the present Linux executor; cgroup is mounted read-only. A generic Linux process backend would not solve the historical identity mismatch.

Clean Astra max review supports the narrower proposal: a new, explicitly versioned, read-only migration DATA verifier for this one history. It executes current trusted validation code, never imports/executes archived source or releases an old owner/native/model/driver worker. This removes that worker's lifecycle dependency by removing its execution, not by reporting a Linux process as a Windows Job. It changes ADR-0053 Decision2/5/7 for this explicit finite route and needs a narrow superseding ADR statement before installation.

## Proposed contract

1. Keep all original files byte-exact. The operation's embedded9e98ad... request, existing binding'sb9ebaf... request and new compensation7dea03... request retain their distinct roles. Match exact original operation/request/frozen effects, original proof/support order, full prompt/schema/serialized request, output/verdict, protocol/runtime and retained execution relations. A manifest hash, `check_retained` data predicate, public receipt or saved result dictionary alone cannot issue a history handle.
2. Preserve old Windows roots, device/inode, command, interpreter and policy identity as immutable historical values. Explicitly map the already verified dataset's source locations to actual currently read files; separately bind current root/file identity, complete actual byte reads and current verifier code/policy identity. A mapping only locates bytes. It does not rewrite the recorded identity or assert that an old physical object exists on this host.
3. Verify full required original source/schema/policy inputs against actual original evidence. Do not substitute current sys.version, a current commit, guessed paths, new source or sanitized text. Old Python need not be installed/executed for this data route, but every original policy input needed for deterministic reconstruction must have actual evidence. Missing data stops only this exact verification at its concrete dependency, without widening Story prerequisites or requiring all Git/history by default.
4. A new versioned authentication output, for example `newrouge.b-route-qualified-historical-migration-auth.v1`, identifies a NEW migration verifier and its explicit claim. Only successful actual complete validation by that implementation may mint its distinct private handle. Never instantiate/relabel the old AuthenticatedHistory class or emit old owned_job_returned/old-owner-executed claims. Exact final schema and integration code remain unimplemented; no output or grant has been minted by this proposal.
5. Selection is explicit for the one approved history/compensation route, with no automatic fallback from an old verifier failure. Old verification families, old source/proof bytes and existing published readers keep their contracts. Reuse existing journal, locks, budget owner and compensation interfaces; add no formal planning database, registry, carrier or seal prerequisite.
6. Current compensation remains separately responsible for actual current-before bytes, scopes, retained post-edits/Task history, identity allocation, pending conflicts, independent review, budgets and catalog-last commit. The new historical verifier grants none of those outcomes. Capacity remains its own existing unresolved issue; unchanged Cap/MVG70k and input-plus-output limits do not increase.

## Bounded implementation and verification after approval

- Add the narrow ADR supplement and explicit versioned consumer/handle with its finite integration route.
- Resolve only references actually consumed by that route against existing batch03 and saved snapshots. Record an exact required input if unavailable; do not request a speculative new full inventory or execute an archived producer.
- Add targeted data-integrity/semantic relation tests for original requests, proof/protocol/output/source/schema/policy and retained support, historical/current identity separation and changed-byte/mapping rejection. Verify no historical code/model/child is dispatched and no original target/ledger is written.
- Attempt one bounded offline verification on the already received actual data after deterministic validation. Preserve all failures and report its exact claim; no duplicate download or full-suite discovery run.
- Retain the existing public read/no-op results. They do not need rerunning for this decision.

This approval would authorize only the limited offline implementation and focused verification. It would not itself authorize a paid model request, funding grant/release, old unknown replay, default B activation or formal Story acceptance. It does not promise the current359 originals contain every required policy input, equivalence before implementation, a capacity pass or Windows fault qualification.

## One decision

Approve the new finite read-only migration DATA verification contract for NativeV15Origin03 and its current compensation, replacing the old-owner execution requirement only for that explicit route; or retain the existing contract and leave this migrated real-compensation route blocked. No larger cross-platform execution framework is required by this proposal.
