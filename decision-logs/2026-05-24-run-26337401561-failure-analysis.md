## Decision

## Consequences
- Previewing a reward offer before entering `Reward.tscn` no longer locks the snapshot or consumes pending modifiers.
- Re-entering the same reward context after resolution still reuses the locked snapshot, but a new route now gets a fresh context instead of inheriting the previous active context.
- Reset helpers now wipe reward selection state along with runtime modifiers, which removes stale route-owned reward state during Task 133 tests.

## Recovery Impact
