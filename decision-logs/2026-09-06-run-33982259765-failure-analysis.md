## Why now

PR #158 的 Windows Quality Gate 在 hard gate 阶段失败，需要基于 CI 工件定位并修复。

## Artifact-backed context

- 运行：`33982259765`，分支 `feat/kcp-impact-analysis-prd`，提交 `3b0f4b92dbfdd659bb34852d8c2c35595d82fc94`。
- `gate-bundle/summary.json`：23 个 hard gate 中仅 `obligations_unittest` 失败；其余门禁通过。
- `obligations_unittest.log`：221 个测试中 18 failures、4 errors。
- 主要异常为 Windows Runner 的 `RUNNER~1` 短路径被路径 containment 校验误判为 `path_outside_repository`，继而连锁影响 revision、dirty-state、publication compensation 和 CLI lock 测试。
- BOM 审计同时因 checkout 缺少完整历史而出现 `unable to enumerate baseline tree`。

## Decision

在 `impact_analysis_index.py` 中统一长短路径规范化后再做 repository containment 判断；在 Windows quality workflow 中设置 `fetch-depth: 0`，确保 baseline archive/tree 可读取。保留 fail-closed 和 reparse-point 检查，不放宽路径边界。

## Consequences

合法的 Windows 临时目录短路径不再被误报；真实越界路径和 reparse-point 仍应拒绝。完整 checkout 会增加少量 CI checkout 时间，但保证基线审计可重复。

## Recovery impact

本修复不改变 KCP authority、Locator threshold 或 generated knowledge state。ACCEPT-01 仍需在 main 合入后重新执行真实链路。
