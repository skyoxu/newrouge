- Why now: The latest downloaded `ci-logs6.zip` and `selfcheck-logs6.zip` artifacts showed that compile-time recovery was fixed, but the shared `.NET` wrapper was still retrying deterministic test failures and thereby manufacturing a second-stage environment corruption pattern.
- Context: `F:\\gitlog\\ci-logs6_unpacked\\2026-05-22\\ci-pipeline-summary.json` shows `selfcheck` fully green and `.NET` failing with 59 named failures. `dotnet-test-output.txt` starts with a normal build (`Game.Core.dll` and `Game.Core.Tests.dll` both built) and then quickly collapses into many `System.IO.FileNotFoundException : Could not load file or assembly 'Game.Core'` failures. The tail proves this happened on `attempt-2` because the recorded results file is `Game.Core.Tests\\TestResults\\attempt-2\\tests.trx`. That means the wrapper retried after an ordinary failing run, even though the retry condition should only apply to the narrow coverlet post-run file-lock abort signature. The existing loop in `scripts/python/run_dotnet.py` only stopped early on `(rc == 0 and not retryable_coverlet_file_lock)`, so any non-zero `dotnet test` result forced another attempt and reopened the path to secondary corruption.
- Decision: Change `scripts/python/run_dotnet.py` so retries happen only when `_is_retryable_coverlet_file_lock_abort(output)` is true. Any non-retryable failure, including ordinary red tests with `rc != 0`, must stop after the first attempt and report that failure directly.
- Consequences: Deterministic test failures are no longer hidden behind a second synthetic run that can pollute the build/test environment and replace the real root cause with `Game.Core` load failures. The wrapper still preserves the previous narrow retry behavior for the known coverlet file-lock abort class.
- Recovery impact: Recovery remains in shared test orchestration. The next CI run should expose the actual first-order failing tests rather than a wrapper-induced second-pass crash signature.
